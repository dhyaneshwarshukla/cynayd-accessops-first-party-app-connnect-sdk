# Security reports and release notices

Report suspected SDK vulnerabilities privately to the SDK repository maintainers using GitHub private vulnerability reporting where enabled. In its absence, use the organization's existing private Security incident channel. Include the affected SDK version, operation stage, sanitized request ID and a minimal description. Keep credentials, token contents, proofs and customer data out of reports.

Maintain a private advisory for the owning teams while fixes are in development. The SDK owner publishes a patched, pinned version with integrity metadata and notifies Connect, Drive, Docs, Grid and other registered consumers through their maintainer contacts. Include affected and fixed versions, upgrade deadline and any key or registration action. Consumers verify the new lockfile and run their target acceptance matrix. Revoke affected credentials through One where necessary.
