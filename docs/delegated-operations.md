# Calling another first-party application

Before a source command, use `host.authenticate` (or `FastAPIHost.authenticate`) and apply the source product’s existing permissions. Keep the HTTP method, HTTPS origin, path and query policy, audience and exact scope in server configuration or code. Give the SDK the live verified host binding and the permitted operation. The SDK obtains a short-lived user delegation from One with a confidential assertion and DPoP, then sends a fresh DPoP proof to the fixed target. The browser receives only the product result. Never return a credential or proxy arbitrary destinations, scope strings, headers, redirects or unchecked target error bodies.

At an existing Node or FastAPI target use `DelegatedResource.authorize` with a separately approved resource client, pinned One JWKS, `PostgresProofReplayStore` (or an atomic shared equivalent), and the existing resource ACL. The verified person, tenant and target installation are inputs to the ACL. One introspection runs for every request. Perform the side effect only on success. For FastAPI use `cynayd_first_party.resource.DelegatedResource` and translate failures with `resource_error_response`. Pass the actual method and request path and the route’s fixed scope. For writes with uncertain outcomes, reconcile by product receipt or version before any retry.

| Docs to Drive | [Drive adapter example](../examples/host/drive-operations.cjs) uses `POST /api/interapp/files/upload` for creation and `PUT /api/interapp/files/:fileId/content` with `If-Match` for edits, both under `cynayd-drive` and `drive:write`. Bind the destination to the authorized document mapping. |
| Mail to Drive | The same example uses upload for a user-selected folder and `GET /api/interapp/files/:fileId/download` with `drive:read` for attachment retrieval. Verify draft ownership and attachment permissions, file bounds, recipient handling and send idempotency at Mail. Require approved Mail grants. |
| Drive to Connect sharing | The available evidence does not establish a Connect receiver with the One DPoP contract or a central Drive sharing-permission route. Obtain a confirmed operation schema, audience/scope and target ACL contract from the owner before implementing the call. Reading Drive bytes or creating a link does not grant the Connect recipient access. |
| Connect to Calendar | Calendar exposes an existing event creation API under `POST /api/v1/events`. The evidence does not establish a One DPoP audience and resource verifier for that route. The SDK’s [Calendar fixture](../examples/connect.cjs) demonstrates the exchange and call shape against an in-process stand-in. Live use requires Calendar to verify the contract, approve the exact audience/scope, and authorize the user on the requested calendar. |
| Groot to first-party applications | See the [Python Drive operation](../examples/host/python-drive-operation.py). For each reviewed and approved tool operation, use the verified current FastAPI subject and identity with Python `DelegationClient.call(subject, identity, operation, public_url, ...)`. Revalidate at execution and resumption, then enforce existing connector approval, tenant and resource policy. The inspected Groot registration is launch-only. Legacy provider scopes do not establish a One grant. |

The Drive examples use routes observed in existing integration source. Check the current deployed write, conditional update, multipart, streaming and ACL behavior with the target owner and an approved test registration before enabling each flow. See [Drive endpoint and verifier evidence](phase2/drive-compatibility.md) and [Calendar and Connect target evidence](connect-handoff.md).

During a target cutover, audit each retained Bearer, service and worker route. A One proof-bound credential presented on a legacy Bearer route must be rejected. Keep OAuth token endpoint errors and resource challenges distinct. The SDK’s resource adapters give invalid token/proof errors a DPoP invalid-token challenge and provide an insufficient-scope challenge for scope failures. Keep legacy provider and independent service credentials on their existing approved paths until their consumers qualify and migrate.
